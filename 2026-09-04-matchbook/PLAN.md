# Matchbook — a from-scratch exchange matching engine + market simulator

## The concept

Every stock, option, crypto, and futures exchange on earth is built around
the same small, brutal core: a **limit order book** that matches buyers and
sellers by **price-time priority**. Whoever bids the most gets filled first;
among equal bids, whoever arrived first gets filled first. That's it. That
one rule, implemented correctly and made fast, is the multi-billion-dollar
business of NASDAQ, NYSE, CME, and every crypto exchange's "matching engine."

Matchbook builds that core from scratch — the real algorithm, not a
simplified toy — and then goes one step further than a static data
structure demo: it wires the book into a **living market**. A population of
independent trading agents (market makers quoting both sides for the
spread, momentum traders chasing trends, noise traders providing random
flow, and one informed trader secretly trading on a signal that will later
become public) all submit real orders to the same book over a simulated
trading session. Nobody scripts the price path — it *emerges* from the
agents' independent decisions colliding in the order book, the same way
real market microstructure emerges from real traders.

## Why it's interesting

This repo has built plenty of "from scratch" systems — languages, VCS,
crypto, renderers, search engines, physics engines, nine transformers — but
never **market microstructure**, the plumbing that decides *who gets to
trade at what price* under contention. It's a small, precisely-specified
algorithm (price-time priority + order types) with an unusually rich set of
correctness invariants to hold it to:

- **Conservation laws**: total shares long == total shares short across all
  agents at all times; every fill decrements exactly one resting order and
  credits exactly one aggressor; nobody's position can drift out of thin air.
- **Price-time priority is checkable mechanically**: given any two resting
  orders on the same side of the same book, the better-priced one (or, tied,
  the earlier one) must always be offered a match first. This is a property
  a test can brute-force-verify against every trade in a whole session.
- **Determinism**: same RNG seed → byte-identical session (same orders, same
  fills, same final book state) — which is also what makes the crash-recovery
  journal replay independently checkable (replay must reconstruct exactly
  the state that was live before the "crash").
- It also produces something to *look at*: real-looking candlestick charts
  and a live order book depth ladder, generated by agent behavior rather
  than hand-tuned to look nice.

## Architecture

```
Order / Side / OrderType / TimeInForce   (order.py)
        |
        v
OrderBook (per symbol)                    (book.py)
  - two price-sorted heaps of price levels (bids: max-heap, asks: min-heap)
  - each price level is a FIFO deque of resting orders (time priority)
  - match(): limit / market / IOC / FOK, partial fills, cancel, replace
        |
        v
Exchange (multi-symbol router)            (engine.py)
  - owns one OrderBook per symbol
  - RiskEngine gate in front of every order (risk.py)
  - every accepted event appended to the Journal (journal.py) BEFORE
    it is applied to book state (write-ahead, so replay is exact)
        |
        v
Journal                                    (journal.py)
  - append-only JSON-Lines log, one line per event, CRC32-checked
  - replay(): rebuild an Exchange from an empty state by re-applying
    every journaled event in order -> used for crash recovery AND as
    the independent "did the live engine actually do what it logged"
    correctness oracle
        |
        v
Agents (agents.py) driven by Simulator (simulator.py)
  - MarketMaker, MomentumTrader, NoiseTrader, InformedTrader
  - each agent only sees public book state (+ the informed trader's
    private signal) and submits real Order objects to the Exchange
  - Simulator is a deterministic seeded discrete-event loop: draws an
    agent, lets it act, advances simulated time, appends trades to a
    tape
        |
        v
Candles (candles.py): aggregates the trade tape into OHLCV bars
        |
        v
Viz (viz.py): renders one self-contained interactive HTML file
  (order book depth ladder, trade tape, OHLCV candlestick chart,
  scrubbable session replay) straight from a finished session's
  journal + trade tape - no server required to view it.

CLI (cli.py): run/replay/inspect/viz/demo subcommands.
```

## Feature list

1. **[REQUIRED] Price-time priority matching engine.** A real limit order
   book: limit orders that rest and are matched by best-price-then-earliest,
   market orders that sweep the book, IOC (immediate-or-cancel: fill what's
   available now, cancel the remainder) and FOK (fill-or-kill: all-or-nothing,
   atomically), partial fills, cancel, and cancel/replace (modify).
2. **[REQUIRED] Event-sourced journal with crash recovery.** Every accepted
   order/cancel/fill is appended to a durable, checksummed, append-only log
   *before* it mutates in-memory state. A `replay()` rebuilds the exact same
   book state from nothing but the journal — demonstrated by literally
   killing the "live" state mid-session and recovering it byte-for-byte.
3. **[REQUIRED] Multi-agent market simulation.** Independent agent
   strategies (market maker, momentum, noise, informed-trader-with-a-signal)
   generate real order flow against the live book over a seeded, fully
   deterministic discrete-event session, producing emergent price action —
   nothing about the price path is scripted.
4. **[REQUIRED] Interactive HTML market visualizer.** A single self-contained
   HTML file (no server) rendering, from one finished session's journal and
   trade tape: a live order-book depth ladder, a scrolling trade tape, an
   OHLCV candlestick chart, and a scrubber that replays the whole session
   tick by tick.
5. **[STRETCH] Risk engine.** Per-agent position limits, self-trade
   prevention (an agent's own resting order is skipped rather than
   self-matched), and fat-finger price collars (orders too far from the
   last trade are rejected) — enforced by a gate every order passes through
   before it reaches the book, with rejections visible in the session log.
6. **[STRETCH] Multi-symbol exchange with cross-symbol portfolios.** The
   `Exchange` runs several independent order books at once (distinct
   tickers), and each agent's portfolio/P&L is tracked across all of them
   simultaneously, so a single simulation session is a real multi-asset
   market, not just one book replicated.

## What "done" looks like

- `matchbook run` simulates a full session end-to-end and prints a summary
  (trade count, close prices per symbol, per-agent P&L, any risk rejections).
- `matchbook replay` rebuilds identical state from the journal alone and a
  test asserts byte-identical equality with the live engine's final state.
- `matchbook viz` produces one HTML file that opens and is fully interactive
  with no server.
- A property-style test suite brute-force checks price-time priority and
  share conservation over many random sessions, not just fixed examples.
