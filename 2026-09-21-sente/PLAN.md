# Sente — PLAN.md

## Concept

Sente is a from-scratch **AlphaZero-style self-play reinforcement-learning game
engine**: a PUCT Monte Carlo Tree Search guided by a learned dual-head
policy+value neural network, where the network is trained *purely from data
the search generates by playing against itself* — no external dataset, no
human games, no supervised corpus. The search uses the network to guide
exploration; the network is trained to predict what the search discovers;
repeated across generations this creates a positive feedback loop between
search and network, which is the entire "AlphaZero" trick.

## Why this is interesting (and why it's genuinely new for this repo)

I read `LEDGER.md` in full before writing this plan, specifically hunting for
anything that already combines tree search with a network trained by
reinforcement from its own self-play. What's actually there:

- **Gambit** (2026-06-18, both the `gambit` and `gambit-8qd3ko` builds) and
  the third chess engine embedded in Gambit's sibling builds: alpha-beta /
  PVS search over a **hand-crafted, static** piece-square evaluation
  function. There is search, but zero learning — the evaluation never
  changes based on outcomes.
- **Cotangent** (2026-06-16) and the nine **Loom** builds (2026-07-07
  through 2026-07-25): from-scratch backprop neural nets (a scalar autodiff
  MLP library, and later GPT-style transformers), all trained by
  **supervised** gradient descent on a **fixed, pre-existing dataset**
  (synthetic classification sets, or a fixed text corpus). There is a
  learned network, but zero search, and the training signal is not
  generated by the model's own decision-making — it's given upfront.
- **Kinesis** (2026-07-12): evolves virtual creature body plans and CPG
  gaits with a **genetic algorithm** (tournament selection, crossover,
  mutation) against a from-scratch rigid-body physics engine. This *is*
  a from-scratch "learning system improves through self-generated
  experience" story, and it's the closest precedent in spirit — but the
  optimization is population-based GA, not gradient-based RL, and there is
  no tree search and no neural policy/value function anywhere in the loop.
- No build anywhere in the ledger runs a Monte Carlo Tree Search, and no
  build trains a network on labels produced by its own inference-time
  search over a game tree.

So: search-guided-by-network-trained-by-search-outcomes (the actual
AlphaZero loop) is new territory for this repo. Kinesis is the nearest
neighbor (self-generated training signal, hand-rolled optimizer, zero-ML-
framework ethos) but is evolutionary rather than search+gradient RL, and
Gambit is the nearest neighbor on the "board game engine" axis but has no
learning at all. I'm keeping this novelty claim honest rather than
maximal: this is a new *mechanism* (search+network co-training), not
a claim that "games" or "hand-rolled neural nets" are unprecedented here —
both of those ingredients separately have precedent, their combination
does not.

## Why Tic-Tac-Toe + a reduced Connect Four

- **Tic-Tac-Toe** (3x3) is small enough that an independent exhaustive
  minimax oracle is trivial to build and cache, giving a hard, checkable
  ground-truth invariant: a fully trained agent must never lose to
  provably perfect play, from either side. That is the strong
  "did it actually learn" proof for this project, in the spirit of
  Gambit's perft counts or Quantum's Belady's-MIN oracle.
- **Connect Four** at the full 7x6 size requires many thousands of
  self-play games per generation and deep trees to reach real strength —
  not tractable on a CPU-only sandbox in this session's time budget.
  Sente instead uses a **5 columns x 4 rows board, 4-in-a-row to win**
  ("Connect Four Jr"). It keeps the *same* mechanics (gravity-drop moves,
  4-in-a-row win detection in all 4 directions, a materially larger
  state/action space than Tic-Tac-Toe so the pipeline is genuinely
  exercised on a second, harder game) while keeping self-play games short
  (at most 20 plies) and the branching factor small (5 actions), so a
  from-scratch, non-vectorized-across-games MCTS in pure Python/NumPy can
  run enough self-play games per generation to show real learning within
  a CPU-only budget. Full 7x6 optimality is not provable this way (its
  game-theoretic value is only known via a specialized solver), so Sente
  only claims — and empirically measures — "beats random and pure-MCTS
  baselines by a wide margin," not "provably optimal," for Connect Four.

## Architecture

- `sente/games/base.py` — an abstract `Game` interface: `initial_state`,
  `current_player`, `legal_moves`, `apply_move`, `is_terminal`, `winner`,
  `encode` (canonical NN input from the perspective of the player to
  move), `action_size`, plus board-symmetry transforms used for training
  augmentation.
- `sente/games/tictactoe.py`, `sente/games/connect4.py` — two concrete
  implementations of that interface.
- `sente/nn/layers.py` — hand-derived forward **and** backward passes for
  every primitive op (`Linear`, `ReLU`, `Tanh`, masked-softmax
  cross-entropy for the policy head, MSE for the value head). NumPy is
  used strictly as a dense-array/BLAS substrate (this repo's established
  precedent from the Loom builds) — no autograd, no ML framework.
- `sente/nn/gradcheck.py` — central finite-difference gradient checker
  run against every op and against the whole composed network before any
  training run is trusted.
- `sente/nn/optim.py` — a hand-rolled Adam optimizer (bias-corrected
  first/second moment estimates, per-parameter).
- `sente/nn/network.py` — the dual-head `PolicyValueNet`: a shared trunk
  of `Linear -> ReLU` blocks feeding a policy head (logits over the
  game's action space, illegal actions masked before softmax) and a value
  head (`Linear -> Tanh`, scalar in [-1, 1]).
- `sente/mcts.py` — generic PUCT MCTS over the abstract `Game` interface:
  configurable simulation count and exploration constant `c_puct`,
  Dirichlet noise mixed into the root prior (self-play only), and
  temperature-scaled sampling from visit counts (high temperature early
  in a game, argmax later, and always argmax with zero noise outside of
  self-play).
- `sente/selfplay.py` + `sente/replay_buffer.py` — self-play game
  generation storing `(encoded_board, mcts_visit_policy, outcome)`
  tuples into a bounded replay buffer, with board-symmetry augmentation.
- `sente/train.py` — the generation loop: self-play with the current
  network -> append to buffer -> train several epochs with Adam ->
  checkpoint -> repeat.
- `sente/oracle_tictactoe.py` — an independent, from-scratch, memoized
  exhaustive minimax oracle for Tic-Tac-Toe (shares no code with the
  network/MCTS) used only for evaluation, never for training.
- `sente/evaluate.py` — the ground-truth harness: (a) the "never loses to
  perfect play" exhaustive/large-sample check against the oracle, run
  with MCTS+network at zero temperature and zero Dirichlet noise; (b) a
  round-robin tournament across generations and baselines (uniform
  random, pure-MCTS-with-uniform-priors-and-random-rollout-value, earlier
  checkpoints) with win-rates and a simple Elo ladder.
- (stretch) `sente/server.py` + `static/index.html` — a Python
  `http.server`-based backend that holds the real network + MCTS state
  server-side (same zero-client-logic pattern as Gambit/Impulse); the
  browser only renders the board and MCTS visit-count/value bars and
  sends move choices over the network.

## Feature list

**Required**
1. Generic PUCT MCTS engine over the abstract `Game` interface
   (configurable simulations, `c_puct`, Dirichlet noise, temperature).
2. From-scratch dual-head policy+value network: hand-derived forward AND
   backward for every op, gradient-checked against finite differences,
   trained with a hand-rolled Adam optimizer.
3. Self-play data generation + iterative multi-generation training loop
   with a replay buffer and checkpointing, run end-to-end on Tic-Tac-Toe
   from a randomly-initialized network to a demonstrably strong player.
4. Evaluation & ground-truth verification: the Tic-Tac-Toe minimax oracle
   + "never loses to perfect play" invariant test, plus a cross-generation
   win-rate/Elo report proving real, measured learning occurred.

**Stretch**
5. Generalize the identical pipeline to the 5x4 "Connect Four Jr" board:
   train a second agent from scratch, and demonstrate it beats random and
   pure-MCTS-no-network baselines by a wide margin (optimality is not
   claimed or provable here — only measured win rate).
6. A server-backed interactive browser UI to play against a trained
   agent, with a live visualization of MCTS per-move visit-count/value
   estimates, verified with zero console errors in headless Chromium.
