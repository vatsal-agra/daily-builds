# Sente

A from-scratch **AlphaZero-style self-play reinforcement-learning game
engine**: PUCT Monte Carlo Tree Search guided by a learned policy+value
neural network, where the network is trained *purely from data the
search generates by playing against itself* — no external dataset, no
human games, no supervised corpus. Search and network improve each other
in a loop; that loop is the entire project.

**Status: shipped.** All 6 phases complete — plan, core build,
adversarial review, both stretch features, verification, ship.

## Why this project, today

I read this repo's full `LEDGER.md` before picking a design (see
`PLAN.md` for the detailed, line-by-line novelty check). The short
version: **Gambit** and its variants (2026-06-18) search a game tree but
never learn — a static, hand-crafted evaluation function. **Cotangent**
(2026-06-16) and the nine **Loom** builds (2026-07) train real
from-scratch neural nets with hand-derived backprop, but only ever on a
fixed, pre-existing, supervised dataset — there is no search and the
training signal isn't generated by the model's own decisions.
**Kinesis** (2026-07-12) is the closest relative in spirit — a
from-scratch optimizer that improves purely from self-generated
experience against a hand-rolled physics engine — but it's a genetic
algorithm, not gradient-based RL, and has no tree search or neural
policy/value function anywhere. **Nothing in this repo's history
combines tree search with a network trained by reinforcement from its
own self-play.** That specific mechanism — search and network training
each other — is what Sente adds that wasn't here before. It's a new
*mechanism*, not a claim that games or hand-rolled neural nets are
individually unprecedented in this repo; PLAN.md is explicit about that
distinction rather than overclaiming.

## What's actually shipped

**Required (4/4):**
1. **Generic PUCT MCTS** (`sente/mcts.py`) over an abstract `Game`
   interface — configurable simulation count and `c_puct`, Dirichlet
   root noise, temperature-scaled visit-count sampling. Sign-convention
   correctness (the single easiest place to get self-play MCTS silently
   wrong) is unit-tested against an independent minimax oracle standing
   in as a "perfect" value function.
2. **From-scratch dual-head policy+value network** (`sente/nn/`) — hand-
   derived forward **and** backward passes for every op (Linear, ReLU,
   Tanh, masked-softmax cross-entropy, MSE), gradient-checked against
   central finite differences (every op individually, plus the whole
   composed network's every parameter, for both games) before a single
   real training step, trained with a hand-rolled Adam optimizer.
   NumPy is used strictly as a dense-array/BLAS substrate — no
   autograd, no PyTorch/TensorFlow/JAX, no RL framework.
3. **Self-play + iterative multi-generation training** (`sente/train.py`,
   `sente/selfplay.py`, `sente/replay_buffer.py`) — run end-to-end on
   Tic-Tac-Toe from a randomly-initialized network to a demonstrably
   strong player, with a real bounded replay buffer that is actually
   consumed by training (not a write-only buffer).
4. **Ground-truth evaluation** (`sente/oracle_tictactoe.py`,
   `sente/evaluate.py`) — an independent, from-scratch, exhaustive
   minimax oracle proves the trained Tic-Tac-Toe agent **never loses to
   perfect play, playing either side**, across every line the oracle can
   force; a cross-generation win-rate/Elo tournament against baselines
   (random, pure-MCTS-with-uniform-priors-and-rollout-value, earlier
   checkpoints) proves real, measured learning happened.

**Stretch (2/2, both shipped fully):**
5. The identical pipeline generalized to **Connect Four Jr** (5 cols x 4
   rows, 4-in-a-row — see "Why these game sizes" below), trained from
   scratch, beating random and pure-MCTS baselines by a wide, measured
   margin (no oracle exists for this game, so optimality is honestly
   *not* claimed).
6. A **server-backed interactive browser UI** (`sente/server.py` +
   `static/index.html`) to play a trained agent live, with a real-time
   visualization of the search's per-move visit-count/value estimates —
   verified for real in headless Chromium, zero console errors.

## How to run it

```bash
cd 2026-09-21-sente
python3 -m pip install -r requirements.txt   # numpy only, no other deps

# Run everything and see a pass/fail summary (recommended first step):
./demo.sh

# Or run each piece individually:
python3 scripts/run_gradcheck.py                    # 1. gradient checks
python3 scripts/run_training_ttt.py                 # 2. self-play train Tic-Tac-Toe (25 gens, ~20s)
python3 scripts/run_oracle_check.py checkpoints/tictactoe/tictactoe_gen025.npz   # 3. "never loses" proof
python3 scripts/run_tournament.py                   # 4. cross-generation Elo report
python3 scripts/run_training_c4.py                  # 5. self-play train Connect Four Jr (50 gens, ~7min)
python3 scripts/run_tournament_c4.py                # 5. its Elo report + baseline margins
python3 scripts/run_server.py                       # 6. serve the UI at http://127.0.0.1:8765/
node scripts/playwright_smoke.js                    # 6. headless-Chromium verification
python3 -m unittest discover -s tests -v            # full unit test suite (38 tests)
```

**Gradient checks** — every primitive op and the whole composed network
(both games) checked against central finite differences:

```

[OK ] Tanh: rel_err=4.7e-11        [OK ] Linear.db: rel_err=1.9e-11
[OK ] Linear (dx): rel_err=7.6e-11 [OK ] policy_cross_entropy_loss: rel_err=7.9e-10
[OK ] mse_value_loss: rel_err=6.5e-11
[OK ] PolicyValueNet[tictactoe]  all 8 param-grad checks: rel_err=7.0e-06
[OK ] PolicyValueNet[connect4jr] all 8 param-grad checks: rel_err=3.5e-07
ALL GRADIENT CHECKS PASSED.
```

**Tic-Tac-Toe training** — 25 generations, 30 self-play games/generation
(750 games), 60 MCTS sims/move, ~20s. Loss actually falls (a real,
consumed training loop, not a no-op buffer): `1.6046 -> 0.6892` total
loss, gen 1 -> gen 25.

**Ground-truth minimax-oracle invariant** — the independent oracle
(verified against the textbook fact that Tic-Tac-Toe has exactly
**5,478** reachable legal states, empty board = proven draw) exhaustively
explores every line where the oracle plays every one of its
game-theoretically optimal moves and the deterministic, zero-noise agent
plays its one chosen move, for the agent as **both** X and O:

```
gen000 (random-init network): FAILED -- 24 losing lines across 505 explored states
gen025 (trained):              PASSED -- 0 losing lines across 908 explored states
```

Not vacuous — an untrained network fails hard, the trained agent never
loses. **The fully-trained agent never loses to perfect play, playing
either side.**

**Cross-generation win-rate / Elo** — Tic-Tac-Toe's tree is shallow
enough (≤ 9 plies) that even a weak network combined with MCTS often
finds exact terminal values by brute search alone, so an MCTS-guided
ladder alone is a surprisingly weak signal of whether the *network*
learned anything (`gen000`-with-search already beats random). A second,
raw-policy-only ladder (zero search, `NetPolicyOnlyPlayer`) isolates the
network's own learned quality — the honest, un-inflated signal:

```
Raw-policy-only ladder (no search): gen000=951.5 (~= random's 948.5)
                                      gen005=1286.9  gen010=1302.3  gen015=1309.5
                                      gen020=1307.2  gen025=1294.1
```

A clean, reproducible jump from "knows nothing" (statistically tied with
random) to "strong player" after just 5 generations of self-play, no
supervised labels anywhere.

**Connect Four Jr** (stretch #5) — 50 generations, 2,000 self-play games,
~7.3 minutes, loss `1.5676 -> 0.9532`. No oracle exists for this game, so
only a measured margin is claimed:

```
Cross-generation Elo:  gen000=1084 (31.8% winrate) -> gen050=1426 (78.6%)
                       pure-mcts baseline = 1229, random baseline = 788
gen050 vs random:      97.5% win rate (57W / 0L / 3D)
gen050 vs pure-mcts:   81.7% win rate (38W / 0L / 22D)
```

**Server-backed UI** (stretch #6) — headless-Chromium smoke test
(`scripts/playwright_smoke.js`, Playwright pre-installed at
`/opt/pw-browsers`): loads the real page, plays real moves against the

## Why these game sizes

**Tic-Tac-Toe (3x3)** is small enough for an exhaustive minimax oracle —
the strong, checkable "never loses" ground truth this project is built
around (in the spirit of Gambit's perft counts or Quantum's Belady's-MIN
oracle). **Connect Four Jr (5 cols x 4 rows, 4-in-a-row)** keeps
Connect Four's real mechanics (gravity-drop moves, 4-in-a-row detection
in all directions) while keeping self-play games short (≤ 20 plies) and
branching small (5 actions) enough that a non-vectorized, pure Python/
NumPy MCTS can run enough self-play in a CPU-only sandbox to show real
learning within this session's time budget — full 7x6 Connect Four would
need far more self-play games and deeper search than that budget allows.
Full detail and honesty notes in `PLAN.md`.

## Phase 3 — adversarial review

See `REVIEW.md` for the complete hostile self-review. Highlights: a real
value-backup sign/ordering bug in MCTS (crediting a parent edge *before*
flipping perspective instead of after — an off-by-one-ply sign error)
was caught via a dedicated minimax-oracle-backed sign test and fixed
before it ever shipped; a metadata bug in the training report
(`new_examples` conflating self-play games with example tuples once the
replay buffer filled) was found and fixed; two pieces of dead/misleading
code (`PolicyValueNet.copy()`, `Adam.zero_grad()`, the latter a
would-be no-op since `backward()` always assigns fresh gradient arrays)
were removed; a missing guard against `n_simulations=0` silently
producing an all-zero training label was added; and the brief's full
self-play/MCTS/RL bug checklist — value-backup sign errors,
terminal-detection gaps, MCTS tree-reuse corruption, replay-buffer
staleness, Dirichlet-noise leakage into evaluation, symmetry-
augmentation bugs, policy/value collapse, temperature-schedule bugs,
silent backprop shape/gradient bugs — was checked item-by-item with
actual measured evidence, not just a code read. A dedicated regression
suite (`tests/test_eval_purity.py`) spies on the real `MCTS.run` calls
every evaluation player makes to prove Dirichlet noise never leaks into
evaluation/tournament play.

## Phase 5 — verification

`./demo.sh` runs, in order: gradient checks; a short *real* from-scratch
self-play+training run in a scratch directory (proves the pipeline
itself runs, not just that pre-baked checkpoints exist); the full
38-test unit suite; the exhaustive minimax-oracle check; the
cross-generation Tic-Tac-Toe Elo report; the Connect Four Jr stretch
report; and a real headless-Chromium smoke test of the server UI —
**7/7 passed, 0 failed, ALL CHECKS GREEN.** Every number quoted in this
README was regenerated from a clean run with the same seeds after every
Phase 3/4/5 change and reproduces byte-identical results (only
wall-clock timing fields differ), itself evidence the pipeline is
deterministic and that the Phase 3 fixes didn't change training
behavior.

## Where a human could take this next

- **Network gating.** Sente always adopts the newest network for the
  next self-play generation. Real AlphaZero only promotes a challenger
  network after it beats the current best in an evaluation match — worth
  adding once training runs get long enough for a bad generation to
  meaningfully set the loop back.
- **Full 7x6 Connect Four.** The `Game` interface and training loop are
  already generic; scaling up would mainly need a faster MCTS (batched
  leaf evaluation, or a compiled/vectorized game implementation) rather
  than new algorithmic work.
- **A convolutional trunk.** The dense MLP trunk works at this board
  scale, but a hand-derived Conv2D + its backward pass (the natural next
  from-scratch-backprop challenge after this one) would let the network
  exploit board locality and should scale much better to larger boards.
- **Network gating + an Elo-tracked ladder UI.** The tournament/Elo
  machinery already exists; a persisted ladder across many training runs
  (rather than one script invocation) would make regressions visible
  over time.
- **Multi-session play on the server.** `sente/server.py` currently
  holds exactly one global game session; per-connection sessions would
  let more than one person play concurrently.
