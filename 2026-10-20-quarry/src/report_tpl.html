Quarry replay report

Scorecard

The same recorded allocation stream, replayed in a fresh process against each allocator. Overhead is the memory the allocator held from the OS at its peak divided by the peak number of bytes the program actually asked for; 1.00× would be perfect. Speed comes from an unverified run, latency percentiles from a run that times each call.

Memory over time

Dashed line: bytes the program has live. Solid lines: what each allocator holds from the OS. The gap between them is fragmentation, metadata and caching; allocators that give memory back drop toward the dashed line when the program frees.

Quarry heap map

Each square is a run of pages in quarry's page heap, sampled through the replay. Green = slab pages (darker is fuller), blue = large allocations, amber = free pages still resident, grey = free pages handed back to the OS (or never touched). Scrub or press play to watch the heap fill, fragment and drain.
