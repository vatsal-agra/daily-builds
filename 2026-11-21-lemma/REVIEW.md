# REVIEW — adversarial pass on Lemma (Phase 3)

Method: I attacked the build as a hostile user in four ways — (1) **soundness attacks** (can I prove
something false or sneak a paradox in?), (2) **~90 probe snippets** covering every command/tactic with
valid, invalid and borderline input (44 of them kept as the table in `tests/test_probes.py`, the rest folded into `test_surface.py` / `test_tactics.py`), (3) **mutation fuzzing**
(random token deletion/duplication/swap/junk on the example files and the prelude, 600 sessions, looking
for crashes and hangs), (4) **proving real theorems** (the whole prelude library: add_comm, mul_comm,
reverse_reverse …) because real proofs hit things toy tests don't.

## Soundness attacks — all rejected
| Attack | Result |
|---|---|
| `def bad : Type := Type` (Type : Type) | rejected by kernel (`Type 1` is not `Type`) |
| `inductive Bad where mk : (Bad -> Nat) -> Bad` | rejected: not strictly positive |
| `mk : List B2 -> B2` (nested occurrence) | rejected (conservatively) |
| `inductive U where mk : Type -> U` | rejected: field lives above U's universe |
| `mk : P Nat -> P A` (non-uniform parameter) | rejected |
| `def loop n := loop n`, `theorem t : False := t`, `f (succ k)` inside `elim` | rejected: not structural |
| `axiom bad : False` then proving `1 = 2` | accepted *but flagged*: `[uses axiom(s): bad]` (see #13) |
| wrong proofs: `2 + 2 = 5` by `refl`, `assumption` with no match, `rewrite` with no pattern | rejected with a goal dump |

## Findings (all fixed unless marked OPEN)
1. **Lexer: `λ` was read as an identifier** because `'λ'.isalpha()` — `fun`-less lambdas never parsed. *Fixed.*
2. **`elim x with end` on an empty type (False) was a syntax error.** *Fixed* (zero branches allowed; missing ctors are reported by the elaborator).
3. **Kernel smart-unfolding bug:** a definition whose unfolding produced *another folded definition* was left folded, so `append (nil) X` did not reduce and `refl` failed on a true equation. *Fixed* (only stuck recursors/partial λs stay folded).
4. **`rewrite` matched up to definitional equality** — `rewrite ih` (`k*0 = 0`) "matched" `succ k * 0` because they are δι-equal, abstracted nothing, and reported progress; `simp [ih]` then looped to a no-op and left the goal open with a misleading message. *Fixed:* rewrite matches syntactically (with metavariables), and `simp` rolls back steps that change nothing.
5. **`rewrite h` with `h : a = b` never matched a bare variable** (the subterm walker skipped free variables). *Fixed.*
6. **β-redexes leaked into goals** — after `cases h as intro x hx` the hypothesis read `(fun k => a + k = b) x`, which `rewrite` cannot see through. *Fixed:* goals/hypotheses are β-normalised when created.
7. **`congr` / `apply Eq.cong` left an unsolved `?A`** (the domain type isn't fixed by first-order unification of the conclusion) which then crashed the motive check. *Fixed:* after unification, types of solved metavariables are propagated back (`?f := succ` ⇒ `?A := Nat`).
8. **`apply Eq.trans` produced the goals in the wrong order** (the middle term `b : Nat` first). *Fixed:* goals that other goals depend on go last (Lean's behaviour).
9. **`exact h1` on a goal containing a pending metavariable crashed** with a raw kernel error ("cannot evaluate Meta"). *Fixed:* `exact`/`assumption`/`refl` unify when the target has metavariables, and goals solved by unification disappear.
10. **Confusing `return` motive error** (`expected: Nat 0`) when the motive isn't a function of the right arity. *Fixed:* explicit arity message with an example.
11. **After an auto-closed rewrite (`x = x`), an extra `refl.` gave "no goals"** with no explanation. *Fixed:* the message says the previous rewrite closed it.
12. **A Python exception inside any phase would crash the CLI.** *Fixed:* every command is wrapped; user input can't produce a traceback (fuzz: 0 crashes / 0 hangs over 600 mutated files).
13. **Axioms were invisible.** A theorem silently depending on an axiom looks the same as a proved one. *Fixed:* every `def`/`theorem` line lists `[uses axiom(s): …]`, and `#print axioms name` reports them.
14. **`simp` treated every `*.eq_*` name as a simp lemma**, including user lemmas. *Fixed:* only equations generated by Lemma are in the default set.
15. **Rewriting inside a dependent type** (e.g. `Vec A n`) failed late with an opaque "kernel rejected" message at the end of the proof. *Fixed:* the rewrite motive is type-checked immediately and the error names the offending rewrite.

## Known limitations (OPEN, documented in README)
* `induction`/`cases` need each *index* of the major premise to be a variable (`v : Vec A (succ n)` is rejected with a clear message); no `generalize`/dependent pattern matching.
* No universe polymorphism: recursors exist for Type 0/1/2 (`T.rec`, `T.rec_1`, `T.rec_2`); `Eq` is stated for `A : Type`.
* Equation lemmas are generated only for the *outermost* `elim` of a definition; nested `elim`s still compile and compute.
* Inductive types may not be nested (`List T` inside `T`) or mutual; positivity is the conservative direct check.
* No implicit arguments: every argument, including types, is written (`Eq.symm Nat a b h`) — tactics hide most of it.

## Re-run
A fresh run of every probe, the examples, and the fuzzer now hits none of the above (`tests/` + `verify.sh`, Phase 5).
Phase 5 also added a *differential* check — kernel vs. auditor on 1,500 random terms and 400 mutated proofs — which found no
disagreement, and a "lying tactic" test (a `refl` that skips its check) which the kernel correctly refuses.
